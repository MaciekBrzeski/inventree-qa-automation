# InvenTree QA Automation — QAHub AI Hackathon 2026

Agent-generated UI + API test suite for the InvenTree Parts module, built by
orchestrating a local LLM (Claude Code + `qa-gemma` via Ollama) against a
reproducible InvenTree instance.

The whole workflow — from scraping the target app's docs, through drafting
test cases, through writing Playwright specs, through running them, through
measuring coverage — is driven by repeatable Claude Code *skills* that live
under `.claude/skills/`.

## Stack

- **Orchestrator**: Claude Code (Opus 4.6, 1M context)
- **Bulk generator**: `qa-gemma` — Ollama alias, rebuilt `FROM qwen2.5-coder:7b`
  (originally gemma4:26b-a4b, pivoted for VRAM fit at 100% GPU on RX 9070 XT)
- **Embeddings**: `nomic-embed-text` (Ollama) → SQLite + `vec0` KNN
- **Vault**: Obsidian at `../docs/` exposes scraped InvenTree Parts docs,
  filtered OpenAPI, design notes, retrospectives, bugs. Both Claude and Gemma
  read it through MCP or native `fs`
- **AUT**: InvenTree 1.3.0 at `http://inventree.localhost`.
  Portable Docker stack: <https://github.com/MaciekBrzeski/inventree-qa-docker>

## Running the suite

Prerequisites:

- Docker Engine 24+ and Docker Compose v2
- Node.js 20+
- Ollama with `qwen2.5-coder:7b` and `nomic-embed-text` pulled (only needed to
  regenerate artefacts — not to run the tests)

```bash
# 1. Boot the AUT (one-off)
git clone https://github.com/MaciekBrzeski/inventree-qa-docker.git
cd inventree-qa-docker && ./setup.sh
# InvenTree now at http://inventree.localhost (admin/changeme)

# 2. Clone this repo
git clone https://github.com/MaciekBrzeski/inventree-qa-automation.git
cd inventree-qa-automation

# 3. Run the API suite
cd automation/api
npm install
npx playwright test --reporter=list

# 4. Run the UI suite
cd ../ui
npm install
npx playwright install --with-deps chromium
npx playwright test --reporter=list
```

The recorder fixture in `ui/fixtures/auth.ts` logs every request the SPA makes
to `../../data/api-ui-gap/per-test-requests.json`. Regenerate the gap report:

```bash
cd agents/rag && npm install
npx tsx api-ui-gap.ts
```

## The skills

`.claude/skills/` contains three reusable Claude Code skills that automate
the discovery → spec → verify → document workflow. Each has a self-contained
`SKILL.md` that any future Claude Code session can invoke.

### `ui-explore` — discovery walker
Drives Playwright to DFS-walk the SPA, clicks every unique `action-*` /
`role="button"` / `role="tab"`, records the resulting API calls into
`data/ui-explore/click-to-api.jsonl`, and emits a snapshot of aria-labels per
visited route. Used to find unknown UI entry points (what button actually adds
a BOM line? a price break? a substitute?).

### `api-ui-gap` — coverage measurement
Wraps the UI test run with a `page.on('request')` recorder, diffs captured
requests against `data/openapi-parts.filtered.json` (83 endpoints, the full
coverage denominator), and emits `data/api-ui-gap/coverage.md` plus
`covered.txt` / `uncovered.txt` / `dead.txt`.

### `qa-coverage-loop` — unified 6-phase loop
Composes the above plus the three doc generators (`build-test-graph.ts`,
`analyze-ui-paths.ts`, `build-coverage-docs.ts`) into a single entry point.
Invoked as `/qa-coverage-loop` or after any "expand coverage / next pass /
close the gaps" request. Phases:

1. **Analyze** — run all doc generators, read the coverage index
2. **Identify** — rank uncovered endpoints by cluster size
3. **Probe** — write a throwaway spec to discover aria-labels for the target
   panel, delete it once the labels are known
4. **Draft** — compose a real spec from `paths/primitives.ts` + `recipes.ts`
5. **Verify** — run the spec in isolation, then the full suite
6. **Document** — regenerate all four Obsidian views, update the retrospective

## Bugs uncovered

Each is a real InvenTree behaviour we found by running the generated tests.
Full reports in `docs/qa/bugs/`.

| ID | Summary |
|---|---|
| **INV-PARTS-001** | `DELETE /api/part/{id}/` returns 400 on active parts. Must `PATCH {active: false}` first |
| **INV-PARTS-002** | OpenAPI schema marks fields required that the API accepts as optional |
| **INV-PARTS-003** | `POST /api/part/` accepts missing `category` although schema marks it required |
| **INV-PARTS-004** | `PUT` on list endpoints does bulk-update instead of 405 |
| **INV-PARTS-005** | `POST /api/part/stocktake/` returns 500 on valid payloads — blocks 2 test cases |

## Agent fixes — what Claude and Gemma learned the hard way

Selected hard-won fixes from the repair loop. Full journal in
`docs/qa/prompts-journal.md` and running log in `docs/qa/design-notes.md`.

### Phase 1 — RAG infra
- `vec0` virtual table rejects a named `INTEGER PRIMARY KEY`. Fix: implicit
  `rowid` + `BigInt` + `Buffer` binding.
- `vec0` KNN requires `AND k = ?` inside the `MATCH` clause, not trailing
  `LIMIT ?`.
- `automation/{ui,api}/tsconfig.json` needed explicit `"types": ["node"]`
  because `moduleResolution: Bundler` didn't auto-resolve `@types/node`.

### Phase 1 — Gemma performance
- gemma4:26b + `num_ctx=131072` → 23 GB model footprint → 45% CPU spill on
  16 GB VRAM → 24 tok/s. Diagnosed via `ollama ps`.
- Pivot: rebuild `qa-gemma` `FROM qwen2.5-coder:7b`, `num_ctx=16384` → 6.3 GB,
  100% GPU, ~14 s/area vs ~3 min/area before.

### Phase 2 — API specs
- qa-gemma wrapped outputs in ` ```typescript ` fences → post-process strip.
- Gemma emitted `ctx.request.get(...)` / `ctx.request({method, url})` — neither
  exists on `APIRequestContext`. Rewrote to `ctx.get / post / patch / delete`.
- InvenTree refuses `DELETE /api/part/{id}/` with 400 on active parts — real
  API constraint, filed as **INV-PARTS-001**. Applied `PATCH {active: false}`
  then `DELETE` to both specs and `afterAll` cleanup hooks.

### Phase 3 — UI specs
- Mantine confirm dialogs: `getByRole('button', { name: 'Delete' })` matched
  the trigger icon, not the dialog button. Fix: scope to
  `page.getByRole('dialog').getByRole('button', { name: 'Delete', exact: true })`.
- `data-disabled="true"` on a menu item means the entity's state blocks the
  action — e.g. active part can't be deleted (INV-PARTS-001). Deactivate via
  API + `page.reload()` before retrying.
- `waitForResponse` timeouts → swap the regex for a diagnostic listener that
  logs every `POST /api/*`, rerun, fix the regex.

### Phase 5–9 — discovery loop
- `page.on('request')` only captures SPA-initiated fetches. Seeding via
  `createAuthedContext` does **not** count toward UI coverage — only
  browser-initiated requests move the paired count.
- Primitives library (`paths/primitives.ts`) extracted after three specs
  independently reimplemented the same navigation chain.
- Virtual feature-area organisation via an `AREAS` map in
  `build-coverage-docs.ts` avoided physical file reshuffling every time a new
  cluster emerged.

## Known limitations

- **Stocktake writes**: blocked on INV-PARTS-005 (500 on valid payload).
- **Thumbs writes**: require `page.setInputFiles(...)` image upload. Out of
  scope for the current loop.
- **PUT variants**: InvenTree's SPA always sends PATCH; PUT endpoints stay
  api-only by design.
- **Bulk collection PUT/PATCH**: SPA sends individual requests, not lists —
  also stays api-only.
