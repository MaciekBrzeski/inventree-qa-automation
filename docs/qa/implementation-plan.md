## Phase 1 — RAG Pipeline + UI Test Case Generation

### 1.1 Build vault scraper

Target: `[file]` `submission/agents/rag/scrape-inventree.ts`

Logic:
1. Start URL: `https://docs.inventree.org/en/stable/part/`
2. Same-origin crawl, limit to `/en/stable/part/` subtree
3. For each page: fetch HTML via `fetch`, parse with `turndown` → markdown
4. Extract `<h1>` as title, build path: `docs/inventree/parts/<slug>.md`
5. Write with frontmatter (source-url, scraped-at, tags)
6. Atomic write: tmp file → rename
7. Emit `scrape-report.json` listing pages + word counts

Steps:
1. `[gemma]` Generate `scrape-inventree.ts` skeleton:
   ```
   npx tsx agents/rag/query.ts --task bootstrap-scraper \
     --prompt-file prompts/scraper.md --out agents/rag/scrape-inventree.ts
   ```
   (bootstrap before rag/query.ts exists: write this one by hand-reviewed Gemma output via Claude direct HTTP call to Ollama — chicken-and-egg)
2. `[claude]` Review + fix, commit
3. `[cmd]` `npx tsx submission/agents/rag/scrape-inventree.ts`
4. `[verify]` `ls docs/inventree/parts/*.md | wc -l` ≥ 8
5. `[verify]` Open Obsidian, spot-check rendering

### 1.2 Build RAG indexer

Target: `[file]` `submission/agents/rag/index.ts`

Logic:
1. Walk `docs/**/*.md` (vault root = `../../../docs` from `rag/`)
2. Parse frontmatter with `gray-matter`
3. Chunk by H2 headings; if chunk >2000 chars, subsplit by H3 / paragraphs
4. For each chunk: call Ollama `/api/embeddings` with `nomic-embed-text`
5. Store in sqlite-vec:
   ```sql
   CREATE VIRTUAL TABLE chunks USING vec0(
     id INTEGER PRIMARY KEY,
     embedding FLOAT[768]
   );
   CREATE TABLE chunk_meta(
     id INTEGER PRIMARY KEY,
     path TEXT, heading TEXT, content TEXT, tokens INT
   );
   ```
6. Emit `chunks.jsonl` audit (path, heading, sha256, tokens)

Steps:
1. `[claude]` Write `index.ts` (reference sqlite-vec docs)
2. `[cmd]` `npx tsx submission/agents/rag/index.ts`
3. `[verify]` `sqlite3 vectors.db "SELECT COUNT(*) FROM chunks"` > 0
4. `[verify]` `wc -l chunks.jsonl`

### 1.4 Build query CLI

Target: `[file]` `submission/agents/rag/query.ts`

Commander CLI flags:
- `--task <name>` (required) — used for journal heading + output routing
- `--system <path>` — system instructions file
- `--prompt <text>` OR `--prompt-file <path>`
- `--context-mode <full|retrieve>` default retrieve
- `--area <name>` — for full mode, filter chunks by frontmatter tag or path glob
- `--top-k <n>` default 8
- `--out <path>` — write final response here (in addition to journal)
- `--input <path>` — optional extra context file (e.g. test failure trace)

Flow:
1. Load system prompt
2. Build context:
   - retrieve: embed user prompt → top-k from sqlite-vec → format as `## <heading> (<path>)\n<content>`
   - full: glob vault by area → concat all chunks (warn if >100K tokens)
3. Call `chat([system, context, user])`
4. Write response to `--out`
5. Journal the full interaction
6. Also echo retrieved chunk IDs to stdout

Steps:
1. `[claude]` Write file
2. `[verify]` `npx tsx submission/agents/rag/query.ts --task smoke --prompt "list three Playwright locator strategies"`

### 1.5 Write system instructions

Target: `[file]` `submission/agents/system-instructions.md`

Contents (structured):
- **Role**: QA engineer for InvenTree Parts module
- **Grounding**: never invent endpoints/fields/selectors not in provided context
- **Output formats**:
  - UI test cases: markdown table with columns `| ID | Title | Preconditions | Steps | Expected | Priority | Tags |`
  - API test cases: same + `Endpoint`, `Method`, `Status`
  - Playwright TS: strict TS, `@playwright/test`, `getByRole`/`getByLabel` preferred, no `waitForTimeout`, case ID in test title
  - Page Objects: class per page, locator properties, action methods, no assertions inside POM
- **Code style**: no comments unless non-obvious why, no console.log, prefer `async/await`
- **ID format**: `UI-PARTS-###`, `API-PARTS-###`, zero-padded 3 digits
- **Refusal rules**: if context lacks info, output `NEED_CONTEXT: <what's missing>` instead of fabricating
